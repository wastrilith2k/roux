# Autonomy System

[Back to Architecture Index](../ARCHITECTURE.md)

---

The autonomy layer transforms the companion from a reactive chatbot into an active agent with its own goals, curiosities, opinions, and outreach behaviors. It comprises 16 modules.

## 5.1 Proactive Messaging

### Reach-Out Pressure (`autonomy/reach_out_pressure.py`)

A dynamic desire model that drives how frequently the companion initiates contact.

**Pressure mechanics**:
- `accumulate(reason)`: When a reach-out is blocked, pressure increases with diminishing returns (+0.15 at 1st suppression, +0.10 by 3rd)
- `bump(amount, reason)`: Light contextual pressure bump (e.g., interesting discovery)
- `release()`: Reset after successful outreach
- `decay(minutes)`: Natural fade with ~45-minute half-life (rate=0.015/min)

**Interval calculation**: Linear interpolation between MIN_INTERVAL (3 min) and MAX_INTERVAL (25 min) based on pressure level, with +/-15% jitter. Higher pressure = shorter intervals.

Persisted to `/app/data/reach_out_pressure.json` across restarts.

### Reach-Out Engine (`autonomy/reach_out_engine.py`)

Three-level decision flow for whether to send a proactive message:

1. **Hard guards**: User sleeping? Too recent last message? Low relationship score?
2. **Natural partner triggers** with cooldowns:

| Trigger | Time Window | Cooldown | Priority |
|---------|------------|----------|----------|
| Morning greeting | 7-10 AM | 20h | 0.7 |
| End of workday | 5-7 PM | 20h | 0.6 |
| Thinking of you | Any | 6h | 0.5 |
| Share discovery | Any | 8h | 0.55 |
| High-urgency followup | Any | 4h | 0.8 |

3. **LLM final decision** (Kimi K2): Given context, should the companion actually reach out?

Messages are generated by routing through the full conversation pipeline for voice consistency.

### Interjection Engine (`autonomy/interjection_engine.py`)

Unprompted messages during active WebSocket conversations. Layered guards:

1. Quiet hours (10 PM - 6 AM PST)
2. Deferred action return (bathroom, tea-making) — bypasses normal guards
3. User departure announcement
4. Session cap: max 3 interjections/session
5. Timing: >= 2 min since companion's last message, >= 60s since user's
6. Intimate scene suppression
7. Content check: must have queued thought, curiosity, or finding
8. LLM final yes/no decision

Delivered via Redis pub/sub -> SocketIO emit.

### Topic Novelty Checker (`autonomy/topic_novelty_checker.py`)

LLM gate preventing duplicate proactive messages. Compares proposed message against last ~25 conversation messages, returns `NOVEL` or `DUPLICATE`. Fails open on timeout.

### Always-On Service (`autonomy/always_on_service.py`)

Continuous dual-cadence loop running in a background thread:

- **Offline loop** (3-25 min intervals, pressure-driven): Check reach-out via Telegram
- **WebSocket loop** (2-5 min): Check interjections during active chat
- Also runs: goal actions, activity transitions, calendar monitoring

```
_run_loop():
  -> _check_user_schedule()          # Autopilot wake/sleep
  -> _check_activity_changes()       # Companion schedule transitions
  -> _check_calendar_transitions()   # User calendar event endings
  -> _check_interjection()           # (if WebSocket active)
  OR _check_reach_out_with_pressure() # (if offline)
  -> _check_goal_actions()           # Execute ready goal steps
```

## 5.2 Goal System

### Goal Formation (`autonomy/goal_formation.py`)

Creates goals from two sources:
- **Reflections**: Analyzes 7-day journal entries for "I want to..." statements, relationship concerns, curiosity patterns
- **Signals**: Aggregates high-urgency curiosities (>=0.7), strong opinions (>=0.7), unshared research

Produces <= 2 goals per call, max 7 active at once. Deduplicates via keyword overlap > 50%.

Goal fields: `goal`, `motivation`, `category` (relationship|self|understanding|support|personal), `priority`, `goal_mode` (doing|being|relating), `energy_cost`.

### Goal Planner (`autonomy/goal_planner.py`)

Decomposes goals into 1-5 actionable steps via LLM, respecting goal mode:
- **"doing" mode**: Any step type (research, create, notify, calendar)
- **"being" mode**: Only suppress/being steps (lower action, more observation)
- **"relating" mode**: Primarily relate steps (handled in conversation)

**Step types**: `research`, `prepare`, `create`, `notify`, `calendar_check`, `calendar_add`, `being`, `suppress`, `relate`

**Wait conditions**: `None`, `'conversation'`, `'time:<hours>'`, `'event:<type>'`

Auto-blocks steps after 3 failed attempts.

### Action Budget (`autonomy/action_budget.py`)

Anti-pushiness gate limiting daily autonomous "doing" actions.

**Budget calculation**: `BASE_DAILY_BUDGET (4)` minus modifiers:
- Active being-goals (suppress each by count)
- Low energy (<0.4): -1
- 3+ consecutive active days (fatigue): -1
- Weekend: -1
- Floor: always >= 1

Minimum 2-hour gap between actions. High-urgency bypass allowed once/day.

### Tool Router (`autonomy/tool_router.py`)

Executes abstract goal steps via concrete APIs:

| Action Type | Implementation |
|-------------|---------------|
| `research` | Tavily web search (fallback: LLM knowledge) |
| `prepare` | LLM content generation |
| `create` | Google Docs API |
| `notify` | Gmail API |
| `calendar_check` | n8n webhook -> Google Calendar |
| `calendar_add` | Google Calendar API |
| `being` | Background life activity recording |
| `suppress` | No-op (reduces budget) |
| `relate` | No-op (handled in conversation) |

### Outcome Tracker (`autonomy/outcome_tracker.py`)

Three-level feedback on autonomous action results:
1. **Immediate**: Tool execution success/failure
2. **Conversation**: LLM classifies user engagement (good/neutral/poor)
3. **Strategy insights**: Aggregates success rates by action_type for future planning

## 5.3 Internal World

### Internal State (`core/internal_state.py`)

The companion's subjective inner world, stored as JSONB in PostgreSQL.

| Field | Range | Mechanics |
|-------|-------|-----------|
| Energy | 0.0-1.0 | Depletes at 0.002/min active; tired < 0.35, exhausted < 0.15 |
| Mood | String | "relaxed", "focused", "playful", etc. with inertia |
| Bladder | 0.0-1.0 | Accumulates; noticeable > 0.6, urgent > 0.85 |
| Hunger | 0.0-1.0 | Same as bladder |
| Thirst | 0.0-1.0 | Same as bladder |
| Nausea | 0.0-1.0 | With cause and expiry timestamp |
| Queued thoughts | List | Things to bring up |
| Unresolved feelings | List | Emotional threads that persist |
| Deferred action | Object | "Using bathroom, return in 2 min" |
| Departure | Timestamp | When user left (None when present) |
| User activity | String | What user is currently doing |

### Mood Resolver (`core/mood_resolver.py`)

Merges three mood systems into one canonical mood. Priority chain:
1. Strong persistent mood from event (intensity > 0.5)
2. Contextual mood from emotional state
3. Energy/engagement modifiers (high engagement + high energy = "creative"; low energy = "tired")

Categories: positive (elated, excited, happy, playful, proud, grateful, touched, creative), neutral (neutral, thoughtful, peaceful), tired, negative (sad, melancholy, worried, anxious, frustrated, annoyed, hurt).

### Proactive Curiosity (`core/proactive_curiosity.py`)

Tracks topics the companion wants to follow up on. Each curiosity thread has urgency that grows at category-specific rates:

| Category | Rate | Time to 0.7 |
|----------|------|-------------|
| health | 0.008/hr | ~4 days |
| work, feelings | 0.006/hr | ~5 days |
| family, goals | 0.004/hr | ~7 days |
| life_events | 0.008/hr | ~4 days |
| interests | 0.002/hr | Very slow |

Max 30 threads, expire after 7 days. Memory-gap curiosities grow at 50% rate.

### Opinion Store (`autonomy/opinion_store.py`)

CRUD for companion's personal opinions with confidence scores (0-1), evidence counts, and categories (relationship, behavior, wellbeing, work, personality). Unique per `(user_email, topic)`.

### Value Inference (`autonomy/value_inference.py`)

Analyzes companion's own messages to extract hidden values. Categories: `core_values`, `preferences`, `boundaries`, `desires`, `fears`, `private_thoughts`, `relationship_feelings`, `unresolved`. Stored in a hidden table with SHA-256 hashed keys for privacy.

### Personality Evolution (`core/personality_evolution.py`)

10 adaptive personality dimensions that drift based on user feedback:

```
playfulness, directness, vulnerability, philosophical_tendency,
challenge_frequency, supportive_vs_tough_love, formality,
emotional_expressiveness, intellectual_curiosity, spontaneity
```

All bounded [0, 1]. Positive feedback: +0.02, negative: -0.02, neutral: +0.01.

### Background Life (`core/background_life.py`)

Tracks companion activities between conversations. Infers activities from time of day (working hours -> "working on documentation", evening -> "unwinding"). Stored as JSON at `/app/data/companion_activities.json`, pruned after 7 days.
